# StraightUp — протокол обмена Arduino ↔ телефон

Транспорт: Bluetooth Classic SPP через HC-05 (виден на телефоне как обычный
последовательный порт, baud **9600**). Каждое сообщение — одна строка JSON,
заканчивающаяся символом `\n`.

Почему не BLE и не Web Bluetooth: HC-05 — это Bluetooth Classic (SPP), а не
BLE. Браузерный Web Bluetooth API умеет работать только с BLE-устройствами,
поэтому обычный сайт не сможет подключиться к HC-05 напрямую. Решение —
нативное приложение (React Native, Android), которое умеет открывать
Classic Bluetooth SPP-соединение через `react-native-bluetooth-classic`.
На iOS Classic SPP к сторонним модулям в принципе недоступен без MFi-сертификации,
поэтому MVP — **Android-only**.

## Ардуино → телефон (поток данных, ~5 Hz, каждые 200 мс)

```json
{"t":"data","pitch":6.2,"base":5.8,"dev":0.4,"alert":0,"batt":-1,"ms":123456}
```

| поле  | тип    | описание                                                              |
|-------|--------|------------------------------------------------------------------------|
| t     | string | тип сообщения: `"data"`                                               |
| pitch | float  | текущий угол наклона, градусы                                         |
| base  | float  | эталонный угол (результат калибровки)                                 |
| dev   | float  | `abs(pitch - base)` — отклонение от эталона                           |
| alert | 0/1    | 1, если отклонение держится дольше HOLD_TIME (плохая осанка подтверждена) |
| batt  | int    | процент заряда батареи, `-1` если датчик напряжения не подключён      |
| ms    | ulong  | `millis()` на ардуино, для отладки/оценки задержек                    |

## Служебные сообщения ардуино → телефон

```json
{"t":"info","msg":"calibrated","base":5.8}
{"t":"info","msg":"pong"}
{"t":"error","msg":"mpu_not_found"}
```

## Телефон → ардуино (команды, строка + `\n`)

| команда              | действие                                                        |
|-----------------------|------------------------------------------------------------------|
| `CAL`                 | пересобрать эталон осанки по текущему положению (3 сек подготовки) |
| `BEEP`                | коротко пикнуть зуммером (проверка звука из "Настроек")          |
| `SET_THRESH:<deg>`    | установить порог отклонения, напр. `SET_THRESH:15`               |
| `SET_HOLD:<ms>`       | установить время подтверждения плохой осанки, напр. `SET_HOLD:3000` |
| `PING`                | проверка связи, ответ `{"t":"info","msg":"pong"}`                |

Настройки `THRESH`/`HOLD` сохраняются в EEPROM Arduino и переживают перезагрузку.

## Маппинг на экран "Настройки" в приложении

- Слайдер **"Чувствительность"** → чем выше чувствительность, тем ниже `THRESH`
  (напр. диапазон слайдера 5–20° инвертирован в UI).
- Радиокнопки **"Интервал предупреждений"** (30 сек / 1 мин / 2 мин) → повторный
  вызов `BEEP` с телефона, пока `alert=1` держится дольше выбранного интервала
  (логика повтора живёт в приложении, чтобы не перезаливать прошивку при смене
  настройки).
- **"Вибрация" / "Звук"** — тумблеры чисто на стороне телефона (Vibration API /
  системные звуки), к прошивке отношения не имеют.

## Одна кнопка "Начать мониторинг"

1. Приложение подключается к HC-05.
2. Отправляет `CAL`.
3. Ждёт `{"t":"info","msg":"calibrated",...}`.
4. Начинает читать поток `data` и писать сессию в локальную историю (AsyncStorage).
