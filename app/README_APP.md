# StraightUp

Posture-tracking companion app for a single-sensor Arduino (Nano +
MPU6050 + HC-05) posture device. React Native (bare CLI), TypeScript,
Android-only.

All application code (`App.tsx`, `index.js`, everything under `src/`) is
complete and functional. What's **not** included is a hand-written native
`android/` Gradle project — see `android/README_NATIVE_SETUP.md` for why,
and follow the steps below to attach one.

## 1. Install JS dependencies

```bash
cd app
npm install
```

## 2. Generate the native Android shell

Native Android projects generated by the React Native CLI are large,
templated, and version-sensitive — hand-authoring one is a common source
of subtle build breakage, so instead generate a throwaway one and copy its
`android/` folder in:

```bash
# outside this project, in a scratch directory
npx react-native@0.74.5 init StraightUpTmp --version 0.74.5 --skip-install
```

Then, from that scratch project:

```bash
cp -R StraightUpTmp/android <path-to-this-project>/app/android
```

This will merge with (overwrite) the placeholder `android/README_NATIVE_SETUP.md`
directory contents — that's fine, keep the file itself if you want, it's
just documentation and gradle will ignore it.

## 3. Rename the app

In the copied `android/` folder:

- `android/settings.gradle`: change `rootProject.name` to `'StraightUp'`.
- `android/app/build.gradle`: set `namespace` and `defaultConfig.applicationId`
  to your chosen package id, e.g. `com.straightup.app`.
- `android/app/src/main/java/.../MainActivity.kt` and `MainApplication.kt`:
  move to match your package id, and update `getMainComponentName()` in
  `MainActivity.kt` to return `"StraightUp"` (matching `app.json`'s `name`
  and the `AppRegistry.registerComponent` call in `index.js`).
- `android/app/src/main/res/values/strings.xml`: set `app_name` to
  `StraightUp`.

## 4. Add Bluetooth permissions

Add these to `android/app/src/main/AndroidManifest.xml` (inside the
`<manifest>` tag, before `<application>`):

```xml
<uses-permission android:name="android.permission.BLUETOOTH" android:maxSdkVersion="30"/>
<uses-permission android:name="android.permission.BLUETOOTH_ADMIN" android:maxSdkVersion="30"/>
<uses-permission android:name="android.permission.BLUETOOTH_CONNECT"/>
<uses-permission android:name="android.permission.BLUETOOTH_SCAN"/>
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
```

- The first two cover Android 12 and below (legacy Bluetooth permissions).
- `BLUETOOTH_CONNECT` / `BLUETOOTH_SCAN` are the Android 12+ (API 31+)
  runtime Bluetooth permissions.
- `ACCESS_FINE_LOCATION` is still required by the OS for Bluetooth Classic
  device discovery/bonding lookups on pre-12 devices.

The app already requests the correct subset of these at runtime via
`PermissionsAndroid` before listing or connecting to devices — see
`src/services/bluetooth.ts` (`requestPermissions()`), invoked from the
Device screen.

## 5. react-native-bluetooth-classic native linking

`react-native-bluetooth-classic` autolinks via the standard React Native
autolinking mechanism — no manual `MainApplication` package registration
should be needed on RN 0.74. If you see it missing at runtime, double
check `android/settings.gradle` and `android/app/build.gradle` still
contain the autolinking `apply from: ... native_modules.gradle` lines from
the generated project (don't strip these out when copying).

## 6. Build & run

With an Android device or emulator connected/running:

```bash
npx react-native run-android
```

## 7. Pairing the HC-05

Before opening the app, pair the HC-05 module with the phone from
Android's system Bluetooth settings (standard PIN is usually `1234` or
`0000`). The app only lists already-paired ("bonded") Classic devices on
the **Устройство** (Device) screen — it does not do discovery/pairing
itself, since `react-native-bluetooth-classic`'s bonded-devices API is the
standard, simplest path for this exact HC-05 use case.

## Demo mode

The app ships with **Демо-режим** available from Settings and the Device
screen. It simulates a full 5Hz data stream (wandering pitch angle,
occasional posture-alert episodes) without any hardware attached, feeding
the exact same app state the real Bluetooth connection would. On first
launch the app also seeds ~2 weeks of plausible demo session history into
local storage, so Statistics / History / Achievements / Profile are
populated immediately. Demo mode is **on by default** so the app is fully
explorable before any device is paired; turn it off on the Device screen
once you connect real hardware.

## Wire protocol

See `src/types/protocol.ts` for the full typed definition of the
JSON-lines-over-SPP protocol this app speaks to the Arduino firmware, and
`src/services/bluetooth.ts` / `src/utils/LineBuffer.ts` for the
line-buffering parser.

## Project layout

```
src/
  theme/         design tokens (colors, spacing, typography)
  types/         protocol.ts (wire format) + domain.ts (persisted models)
  services/      bluetooth.ts (real device), demoSimulator.ts, dataSource.ts (shared interface)
  storage/       AsyncStorage-backed sessions/profile/settings/achievements + demo seeding
  context/       PostureContext.tsx - central app state (connection, live posture, session, settings)
  navigation/    RootNavigator.tsx - bottom tabs, each wrapping its own stack
  screens/       one file per screen (10 screens total)
  components/    reusable UI building blocks
  data/          hardcoded exercise + achievement definitions
  utils/         small helpers (date formatting, line buffering, id generation, event emitter)
```


## StraightUp: выбор источника данных (3 MPU6050)

На экране **Устройство** два режима: **Демо-данные** (синтетические показания
всех трёх датчиков раз в секунду) и **3 датчика · HC-06** (реальный поток
JSON от Arduino Nano). Источник сохраняется между запусками в AsyncStorage.
При активном мониторинге менять источник нельзя: сначала завершите сеанс.
При переключении последние показатели очищаются, чтобы не принять демо за
реальные измерения. История сеансов сохраняет признак `demo`.

Режим HC-06 работает с Android Bluetooth Classic: сначала выполните
сопряжение в настройках Android, затем выберите устройство в приложении.
Все три MPU6050 подключаются к отдельным каналам 0, 1, 2 TCA9548A,
подключённого по I2C к Nano. Прошивка: `../firmware/straightup_3mpu/`.

**Ограничение:** исходный репозиторий не хранит полный нативный проект
`android/`; CI создаёт его при сборке. APK и реальная Bluetooth-связь должны
проверяться на Android-устройстве.
